Host config on exedore.dc2.crunchtools.com that these units depend on (RT#1628).

ON-SITE COPY (what ColdCopy.service writes, monthly)
LV cs_exedore/onsite on the internal NVMe, LUKS2, TPM2-only: no passphrase and no
recovery key, on purpose. It is a copy of pCloud, so if the TPM is lost the fix is
to reformat it and run ColdCopy again. No PCR binding: Secure Boot is off by
decision, so PCR 7 would add nothing and break on firmware updates.
  /etc/crypttab: onsite UUID=<luksUUID of cs_exedore/onsite> none tpm2-device=auto,nofail,x-systemd.device-timeout=30s
  /etc/fstab:    /dev/mapper/onsite /var/mnt/onsite xfs defaults,nofail,x-systemd.device-timeout=30s 0 2

OFFLINE COPY (4 TB USB drive, unplugged, refreshed once a year by hand)
LUKS2 UUID e692da8c-d6fe-4809-9f01-8f686ace1149. Slot 0 is the BitWarden
passphrase; slot 1 is Exedore's TPM (no PCRs), so on Exedore it opens without the
passphrase. NOT in crypttab/fstab: it must never auto-mount.
  Plug it in, then: systemctl start OfflineCopy.service   (hours; journalctl -fu)
  OfflineCopy.service does the whole procedure: stop ColdCopy.timer, TPM-open,
  mount, ColdCopy from live pCloud, then ALWAYS umount, close and restart the
  timer, success or failure. Unplug only when /dev/mapper/shelf is gone. The
  checklist wraps it: josui-skills skills/annual-checklist/scripts/
  offline-copy-refresh.sh.

VERIFY (on demand, after a copy): systemctl start ColdVerify.service
  pbs -V against live pCloud with /var/mnt/onsite mounted read-only. Refuses to
  start during a copy. The monthly checklist runs it after a fresh ColdCopy run
  (josui-skills onsite-copy-run.sh, then onsite-copy-verify.sh).

/etc/rclone.conf -- Exedore's OWN pCloud token (never copy another host's;
authorizing elsewhere revoked lotor's once). 0600 root.
